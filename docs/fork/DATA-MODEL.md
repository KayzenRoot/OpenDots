# Data Model

This fork uses **two datastores** (accepted decision ADR-0003):

- **PostgreSQL** — conversations only: threads, messages, runs, streamed
  events, thread state, and the local learning/skills store.
- **SQLite** (`node:sqlite` `DatabaseSync`, WAL, default
  `data/opendots.sqlite`) — everything else: workspace, pages, tasks, memories,
  MCP connections, computer permissions, settings, setup telemetry.

Section 1 defines the PostgreSQL schema (PLANNED, WORK-003/WORK-006). Section 2
lists the SQLite tables that stay local (DONE, retained from upstream).

---

## 1. PostgreSQL conversation schema (PLANNED — WORK-003)

Managed by `src/server/pg.ts` (pool + idempotent versioned migrations) and
`src/server/conversation-store.ts`. All migrations are applied in order and
recorded in `schema_migrations`; applying them twice is a no-op.

### 1.1 Conventions

- `id` columns are `text` (UUID strings generated by the app), matching the
  existing app convention rather than Postgres `uuid`, so values are directly
  comparable to the SQLite `thread_bindings.id` and client-supplied IDs.
- Timestamps are `bigint` epoch **milliseconds** (`created_at` etc.), matching
  the SQLite integers, not `timestamptz`. This keeps one representation across
  both stores. (If native timestamps are preferred, this is an ADR-revisable
  choice; it is recorded as epoch ms for fidelity.)
- `owner_id` scopes every conversation row to the workspace owner.

### 1.2 `schema_migrations`

| Column       | Type      | Constraints   |
| ------------ | --------- | ------------- |
| `version`    | `integer` | `PRIMARY KEY` |
| `name`       | `text`    | `NOT NULL`    |
| `applied_at` | `bigint`  | `NOT NULL`    |

Index: primary key on `version`. Migrations are applied in a transaction; a
failed migration leaves the database at the last successful version.

### 1.3 `conversations`

One row per conversation (upstream "thread").

| Column                   | Type      | Constraints / notes                                                 |
| ------------------------ | --------- | ------------------------------------------------------------------- |
| `id`                     | `text`    | `PRIMARY KEY`                                                       |
| `owner_id`               | `text`    | `NOT NULL` — workspace owner                                        |
| `dot_id`                 | `text`    | `NOT NULL` — specialist agent (Dot)                                 |
| `title`                  | `text`    | `NOT NULL`                                                          |
| `learning_container_id`  | `text`    | `NULL` — learned-skills scope (local, replaces hosted container id) |
| `skill_delivery_enabled` | `boolean` | `NOT NULL DEFAULT false`                                            |
| `archived_at`            | `bigint`  | `NULL` — set by thread archive                                      |
| `created_at`             | `bigint`  | `NOT NULL`                                                          |
| `updated_at`             | `bigint`  | `NOT NULL`                                                          |

Indexes:

- `conversations_pkey` on `(id)`.
- `conversations_owner_updated` on `(owner_id, updated_at DESC)` — conversation
  list ordering.
- `conversations_dot` on `(dot_id)`.

### 1.4 `messages`

One row per persisted user/assistant/tool message.

| Column            | Type     | Constraints / notes                                            |
| ----------------- | -------- | -------------------------------------------------------------- |
| `id`              | `text`   | `PRIMARY KEY`                                                  |
| `conversation_id` | `text`   | `NOT NULL REFERENCES conversations(id) ON DELETE CASCADE`      |
| `seq`             | `bigint` | `NOT NULL` — monotonic per conversation; ordering key          |
| `role`            | `text`   | `NOT NULL` — `user` \| `assistant` \| `tool` \| `system`       |
| `content`         | `jsonb`  | `NOT NULL` — string or AG-UI content parts                     |
| `name`            | `text`   | `NULL` — tool name when `role='tool'`                          |
| `tool_call_id`    | `text`   | `NULL`                                                         |
| `metadata`        | `jsonb`  | `NULL` — e.g. `opendotsSource` (voice receipt, scheduled task) |
| `created_at`      | `bigint` | `NOT NULL`                                                     |

Indexes:

- `messages_pkey` on `(id)`.
- `messages_conversation_seq` unique on `(conversation_id, seq)` — ordering and
  idempotency of appends.
- `messages_tool_call` on `(conversation_id, tool_call_id)` where
  `tool_call_id IS NOT NULL` — tool-result lookup.

The `getThreadMessages` part of the `PageIntelligence` seam reads this table
(plus `messages.metadata`) to build conversation→page saves.

### 1.5 `thread_runs`

One row per agent run (a single turn execution).

| Column            | Type     | Constraints / notes                                                 |
| ----------------- | -------- | ------------------------------------------------------------------- |
| `id`              | `text`   | `PRIMARY KEY`                                                       |
| `conversation_id` | `text`   | `NOT NULL REFERENCES conversations(id) ON DELETE CASCADE`           |
| `agent_id`        | `text`   | `NOT NULL` — Dot id                                                 |
| `status`          | `text`   | `NOT NULL` — `running` \| `completed` \| `failed` \| `cancelled`    |
| `error`           | `text`   | `NULL` — sanitized failure class only (never raw provider messages) |
| `started_at`      | `bigint` | `NOT NULL`                                                          |
| `finished_at`     | `bigint` | `NULL`                                                              |

Indexes:

- `thread_runs_pkey` on `(id)`.
- `thread_runs_conversation_started` on `(conversation_id, started_at DESC)`.
- `thread_runs_status` on `(status)` where `status='running'` — recovery of
  interrupted runs on boot.

### 1.6 `thread_events`

Append-only AG-UI event log, used to back `getThreadEvents` and to rebuild the
client stream after reconnect.

| Column            | Type     | Constraints / notes                                       |
| ----------------- | -------- | --------------------------------------------------------- |
| `id`              | `bigint` | `GENERATED ALWAYS AS IDENTITY PRIMARY KEY`                |
| `conversation_id` | `text`   | `NOT NULL REFERENCES conversations(id) ON DELETE CASCADE` |
| `run_id`          | `text`   | `NULL REFERENCES thread_runs(id) ON DELETE SET NULL`      |
| `seq`             | `bigint` | `NOT NULL` — monotonic per conversation                   |
| `event`           | `jsonb`  | `NOT NULL` — the AG-UI event payload                      |
| `created_at`      | `bigint` | `NOT NULL`                                                |

Indexes:

- primary key on `(id)`.
- `thread_events_conversation_seq` unique on `(conversation_id, seq)`.
- `thread_events_run` on `(run_id)`.

### 1.7 `thread_state`

Key/value snapshots of agent state per conversation (backing
`getThreadState`).

| Column            | Type     | Constraints / notes                                       |
| ----------------- | -------- | --------------------------------------------------------- |
| `conversation_id` | `text`   | `NOT NULL REFERENCES conversations(id) ON DELETE CASCADE` |
| `key`             | `text`   | `NOT NULL`                                                |
| `value`           | `jsonb`  | `NOT NULL`                                                |
| `updated_at`      | `bigint` | `NOT NULL`                                                |

Keys: `PRIMARY KEY (conversation_id, key)`. Upsert on write; `getThreadState`
assembles the current key/value map.

### 1.8 `skills` (PLANNED — WORK-006)

Local per-Dot learned skills, replacing hosted learning containers and
`getLearnedSkillsSnapshots`.

| Column             | Type      | Constraints / notes                                                             |
| ------------------ | --------- | ------------------------------------------------------------------------------- |
| `id`               | `text`    | `PRIMARY KEY`                                                                   |
| `owner_id`         | `text`    | `NOT NULL`                                                                      |
| `dot_id`           | `text`    | `NOT NULL` — skill belongs to one Dot                                           |
| `scope_key`        | `text`    | `NOT NULL` — the conversation's `learning_container_id` or a stable per-Dot key |
| `name`             | `text`    | `NOT NULL`                                                                      |
| `content`          | `jsonb`   | `NOT NULL` — skill body/definition                                              |
| `revision`         | `integer` | `NOT NULL DEFAULT 1`                                                            |
| `delivery_enabled` | `boolean` | `NOT NULL DEFAULT true`                                                         |
| `created_at`       | `bigint`  | `NOT NULL`                                                                      |
| `updated_at`       | `bigint`  | `NOT NULL`                                                                      |

Indexes:

- `skills_pkey` on `(id)`.
- `skills_dot_scope` on `(dot_id, scope_key)`.
- `skills_scope_delivery` on `(scope_key)` where `delivery_enabled` — snapshot
  query for a turn.

### 1.9 Retention and cleanup notes

- `thread_events` is the fastest-growing table; retention is policy-driven
  (PLANNED, see SCOPE deferred items). A practical default is: keep events for
  the N most recent runs per conversation, or for a fixed window (e.g. 90 days),
  and compact older events into the corresponding `messages`. The schema
  supports `DELETE ... WHERE created_at < threshold` with no cascade damage.
- `messages`, `thread_runs`, `thread_state` retention follows the conversation;
  deleting a conversation cascades.
- `conversations.archived_at` marks archives without deleting rows; archived
  conversations are excluded from the default list but remain queryable.
- Vacuum/analyze: rely on Postgres autovacuum; `thread_events` benefits from a
  tuned autovacuum scale factor once volume is known.

### 1.10 Migration and backup implications

- Migrations are idempotent and versioned; a clean install and an existing
  database converge to the same schema (OPS-006).
- The Postgres data volume is separate from the SQLite volume; both must be
  included in backup/restore (see [DEPLOYMENT.md](./DEPLOYMENT.md)).

### 2.1 Relationship between the two stores

The two stores are joined by **application-level ID references only**, not by
database foreign keys:

- `thread_bindings.id` (SQLite) is the conversation/thread id; the corresponding
  `conversations.id` lives in Postgres. The runtime and the workspace store agree
  on this id (it is generated once and passed to both).
- `page_threads.threadId` (SQLite) references the same conversation id.
- `mcp_approvals.threadId`, `mcp_actions.threadId`, and `task_threads.threadId`
  (SQLite) reference the same conversation id.
- `computer_audit` and `calls.threadId` likewise.

This means: **a Postgres restore and a SQLite restore must be consistent with
each other.** Restoring one without the other can leave bindings pointing at
conversations that no longer exist (or vice versa). The backup/restore
procedure in [DEPLOYMENT.md](./DEPLOYMENT.md) treats them as one recovery unit
and specifies the reconciliation query.
